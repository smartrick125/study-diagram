# 学习图

用户用图把学到的链路和规律固定下来，以后会反复复习。所以**内容错一处比画得丑更糟**：先保证事实对，再保证图能看清。

本 skill 解决两个问题：

| 问题 | 用什么图 |
|---|---|
| **路线**：不知道要学懂它，还得先懂哪些、有哪些没听过的环节 | 关联图（学前地图） |
| **顺序**：不知道这些知识点在实际过程中按什么先后发生 | 时序图 / 流程图 |

新主题默认先画学前地图看清路线，再按需要画时序图讲顺序。

## 模块目录（先选模块，再读对应文件）

| 模块 | 什么时候用 | 文件 |
|---|---|---|
| 路线 · 学前地图 | 「今天要学 X」「先画个联系图」、给了学习计划 | `modules/路线-学前地图.md` |
| 学后串联 | 「把今天学的串起来」「这些之间什么关系」 | `modules/学后串联.md` |
| 顺序 · 时序图 / 流程图 | 过程、阶段、先后、推导步骤 | `modules/顺序-时序图.md` |
| 核对已有图 | 「这图对吗」「有问题的改一下」、发来图片 | `modules/核对已有图.md` |
| 函数曲线 | 「画个曲线」、参数怎么影响结果 | `modules/函数曲线.md` |

两种关联图都要先读 `modules/关联图-通用画法.md`。按学科再读：渲染 / GPU / Unity → `references/subjects/rendering.md`；数学 → `references/subjects/math.md`。其他学科暂时没有专用文件；画了好几张后，可以把易错点整理成 `references/subjects/<学科>.md`。

## 总流程

1. **选模块**（上表）。
2. **列知识点清单（防漏点，所有模块都做）**：把要上图的知识点逐条编号（K1、K2……），来源是对话、用户给的笔记或图片（学前地图则是学习计划 + 按主题补全）。清单按「讲过什么」列，不按「图里放得下什么」列。
3. **按模块文件写源码**，先放 scratchpad，与图同名：图 `NN-标题.mmd` / `NN-标题.py`，关联图另有 `NN-标题.关系.md`。
4. **渲染**（下方命令）。
5. **看图验收**（不能跳过）。
6. **存档**（只在用户要求时）。
7. **汇报**。

## 通用规矩

- 碰到版本号、默认值、硬件参数这类会过时的事实，先搜索确认再画进图里。
- **范围一致**：图里的数值、结论要和所学对象的范围一致。学具体对象（某个项目、某家厂商）可以写它特有的值，但要标明是谁的，如「本项目：采 5 次」「NVIDIA：一组 32 个线程」；学通用基础只写绝大多数情况都成立的规则，不拿某一家、某一个项目的值当通用结论。两种都要讲时两个都画，各标范围（通用 / 某厂商 / 本项目），用「对比」连起来。本 skill 自己的规则文件也照这条写。
- **数字读到出处**：节点里的具体数字，用户给了对应的代码、工程或资料时，要读完真正产生这个数字的整个函数 / 整段再写，只看调用列表或目录不算；来源写 `代码 文件:行`。理论值和实际值不一致时两个都画，用「对比」连起来。
- **写出前提**：结论只在某个可调参数取某个值时才成立（如次数、开关、系数），就在节点第二行写 `前提：参数 = 值`。关联图、时序图都适用。
- **改过的节点或曲线标红**：`classDef fix stroke:#d32f2f,stroke-width:3px`。红色只用于纠错，用户靠它认出被纠正过的地方。
- 每行文字不超过约 25 个汉字。写法细节和坑见 `references/layout-fixes.md`。
- 不要在图里替用户写出还没做的自测题答案。

## 渲染

```bash
# 流程图 / 时序图 / 关联图：自动找 Chrome / Edge，从 jsdelivr 加载 mermaid（需要联网）
python C:/Users/21265/.claude/skills/study-diagram/scripts/render.py 03-xxx.mmd --out <输出目录>

# 曲线图：需要 matplotlib；脚本里已注入 plt、np、mark()、save()
python C:/Users/21265/.claude/skills/study-diagram/scripts/plot.py 08-xxx.py --out <输出目录>
```

渲染到 scratchpad 里，并把图发给用户看。

## 看图验收（不能跳过）

- 用 Read 打开每张 PNG，检查：文字截断、溢出框、子图标题被压、线缠成一团或穿过别的节点、标注压线、公式排版。有问题按 `references/layout-fixes.md` 修改后重画，直到看得清。源码看着正确不等于图能看。
- **覆盖核对**：拿知识点清单逐条对，每个 K 都要在图里找得到；补不进主线的放进 `待关联` 区，不能默默丢掉。
- 再做所选模块文件里的「验收」。

## 存档（只在用户要求时）

- **默认不存档**：图留在 scratchpad，发给用户看就结束。不要自己去找或新建图片文件夹。
- 用户说要存时，存到用户指定的位置；没说位置就问一句。PNG 和源码放一起（源码可放同级 `源码/` 子文件夹），文件名 `NN-标题`，NN 接着该文件夹现有最大序号往下编。存完列一遍文件夹，确认编号连续、源码齐全。

## 汇报格式

用户有 ADHD，汇报要能直接照着做：

1. 第一句给结论：画了什么 / 几张对、几张改了；存了就写存在哪，没存就说「要存的话告诉我位置」。
2. 覆盖结果：「清单 N 个知识点，图里 N 个」。
3. 所选模块文件里的「汇报要点」。
4. 最后给一个 2 分钟内能做完的下一步，通常是一道判断题，用来检查刚学或刚纠正的点。
