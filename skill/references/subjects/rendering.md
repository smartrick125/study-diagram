# 渲染 / GPU 流程图里反复出现过的事实性错误

核对用户的图时，优先查这几类。每条：错误说法 → 正确说法。

## CPU / 驱动 / Unity 分工
- 「驱动根据 C# 读写声明插 barrier」→ 驱动看不到 C# 声明；DX12/Vulkan 下由 Unity（RenderGraph / 图形后端）插 barrier，驱动只翻译执行。DX11/GL 才是驱动暗中跟踪。
- 「barrier 只做一次」→ barrier 每帧都录、每帧都执行。只做一次的是 shader 翻译成机器码（建 PSO）。
- 「跨平台图形 API（统一接口）」→ DX12、Vulkan、Metal 各是各的接口；统一接口是 Unity 自己的 GfxDevice 抽象层。
- 「驱动把数据写进显存」→ 驱动（软件，跑在 CPU 上）只申请显存、转格式、派任务；真正搬数据的是 GPU 上的拷贝引擎（硬件），经 PCIe 搬运。
- 「懒上传：第一次采样时才进显存」→ GPU 执行中途没法让 CPU 补传；懒上传发生在驱动提交用到它的 draw 之前。

## 硬件结构
- 光栅化是固定硬件，不在计算单元（SM）里。
- 缓存分两层：L1 / 纹理缓存 + 常量缓存每个 SM 各一份（在 SM 内部）；L2 全芯片共用一个（在所有 SM 外面）。
- 常量缓冲（σ、权重）经常量缓存「读一次、广播给整组 32 个像素」，不占每像素寄存器，也不是 L2。
- 「核心」= CUDA 核心 = 一个计算通道，不是 CPU 那种完整核心；32 个一排执行同一条指令。4060：24 SM × 128 = 3072。
- 一个 SM 有 4 个调度器，每周期各挑一个就绪的组发指令 —— 不是「一次算一组」。
- 一组像素：NVIDIA 32；AMD 32 或 64。SM 最多挂约 32～64 组（看架构）。

## 寄存器
- 寄存器个数 = 同一时刻同时活着的变量峰值，不是变量求和。
- 数组长度写死是 HLSL 语法要求；运行时下标访问的数组可能被挪到显存。

## 缓存命中
- 命中也要等（几十～一百多周期），等的时候调度器同样切去算别的组；未命中要几百周期。

## 版本类事实（会过时，用前要搜索确认）
- Unity 6.0 Windows 默认 DX11；Unity 6.1 起新项目默认 DX12。
- PCIe 4.0 x16 ≈ 32 GB/s；4060 显存 ≈ 272 GB/s；4090 ≈ 1000 GB/s；4060 L2 24 MB，4090 72 MB。
