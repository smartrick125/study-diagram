# 核心想法（用户原意，借鉴来的东西不能推翻）

改这里的任何一条都要用户明确同意。新想法按日期追加。

## 2026-10-11

- **起源**：从 10 周学习计划里来。最早是为了把对话里讲清楚的知识画成图、核对已有的学习图。
- **全局版要通用**：平时的总结没有固定的学习记录位置，**默认不存档**，需要存时用户会说。10Week 里另有一份专用版，保留它自己的存档规则。
- **主要目的：把零散的知识点串联起来。**
- **只有时序图容易丢知识点**：之前学一个时序图改了好多遍，老是落下知识点。
- **解决两个问题**：
  1. **路线**：不知道相关的知识需要学什么。→ 关联图（学前地图）
  2. **顺序**：不知道知识点发生的顺序。→ 时序图
- **每次学习前先画联系图**，为了避免盲点。例：之前不知道 GPU 驱动和显存之间还有 GPU 拷贝引擎。
- **每次学习都有具体计划**，关联图围绕当天主线，**不能画太多**。
- **主线和非主线要区分**：比如今天学矩阵运算，有的知识点和它有关但不是主线，要和主线区分开。
- **构成它的基础知识是重点**：不了解向量运算、线性变换就没法了解矩阵运算，这些前置基础是需要重点了解的。
- **长期做、模块化扩展**：以后会不断加入不同模块。
- **每次加新模块新功能，先上 GitHub 找类似的优化方案**，看看什么可以用。保留用户的想法，不停优化。
- **做成公共项目**：用户可能会换用别的 AI（每月只付得起一个），所以规则要写清楚，任何 AI 都能接着维护。
- **适用所有类型的知识，不只是数学**：用户目前用它学渲染、数学、AI agent 自动化搭建、英语等。模块可以继续扩展。
- **路线要回答方向和权重**：学习路径往哪个方向走，每个部分占多大分量（哪些是重点基础，哪些是支线）。
- **顺序对工程知识尤其重要**：比如渲染里各步骤的前后逻辑。
