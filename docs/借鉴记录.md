### B-001 LLMapper skill

- 来源：https://github.com/jorgearango/llmapper-skill （prompts/summarize.md、prompts/rdf.md）
- 做法：先定焦点问题 → 抽 10 个核心概念 → 写「名词 动词 名词」三元组（RDF 作为正本）→ 生成 mermaid；禁止「相关」「涉及」这类空泛关系；主动找对比概念；同义概念合并。
- 采纳：三元组先行、三元组是正本、具体动词、禁止空泛关系、主动找对比、同义合并、关系里出现名词就拆成节点。
- 不采纳：「最多 10 个概念」——用户目标是不漏点，改用分层上限 + 待关联区。

### B-002 Metacademy

- 来源：https://hunch.net/?p=2714 ；编辑规范 https://github-wiki-see.page/m/metacademy/metacademy-content/wiki/Editing-guidelines
- 做法：前置知识图（「知识包管理器」），选一个概念自动展开前置、生成学习计划；每个节点有学习目标、预计时间。
- 采纳：只有「不懂 A 就看不懂 B」才算前置；只需前置的一部分时写清哪部分；间接前置不重复连线；节点粒度约半小时；学前地图汇报里的「今天学完能做到」。
- 待定：每个节点的预计学习时间（路线图候选）。

### B-003 Novak 概念图

- 来源：Novak & Cañas《The Theory Underlying Concept Maps》https://users.cs.northwestern.edu/~paritosh/papers/sketch-to-models/Novak-Canas-TheoryUnderlyingConceptMapsHQ.pdf
- 做法：从焦点问题出发；先把候选概念列进「停车场」（parking lot），用不上的留在那里；连线上写连接词构成命题；跨区域的连线叫 cross-link。
- 采纳：焦点问题当图标题；「停车场」= 待关联区（印证了用户的做法）。
- 待定：cross-link 单独高亮（往往就是盲点）。

### B-004 知识空间理论（KST）

- 来源：https://en.wikipedia.org/wiki/Knowledge_space ；R 包 kst https://r-packages.io/packages/kst
- 做法：已知学习者会哪些后，算出「外缘」（outer fringe）= 前置都满足、现在就能学的知识点。ALEKS 用它决定下一步教什么。
- 采纳：暂无。
- 路线图候选：「下一步学什么」模块——用户回答「前置里哪些已经会了」后，给出现在就能学的点。

### B-005 Breadcrumbs

- 来源：https://github.com/SkepticMystic/breadcrumbs ；文档 https://publish.obsidian.md/breadcrumbs-docs
- 做法：给笔记之间的链接加类型：up/down = 层级，next/prev = 顺序；可渲染成 mermaid。
- 采纳：暂无。
- 路线图候选：三元组里加关系类型（前置 / 组成 / 下一步），**同一份数据同时生成学前地图和时序图**，正好对应「路线」和「顺序」两个问题。

### B-008 Google 开发者文档风格指南 · Jargon

- 来源：https://developers.google.com/style/jargon
- 做法：读者熟悉、或会拿去搜索的术语可以保留；反复出现的术语，第一次出现时在括号里简短解释，或链接到可信的定义。

### B-009 Simple English Wikipedia · 写作指南

- 来源：https://simple.wikipedia.org/wiki/Wikipedia:How_to_write_Simple_English_pages
- 做法：优先用常见词；难词需要时照写，但在括号里解释它是什么意思。
- 采纳：同上，「保留难词 + 紧跟解释」。解释本身只用常见词，不再带新术语。

### B-010 Mayer 多媒体学习 · 预训练原则（pre-training principle）

- 来源：Mayer《Multimedia Learning》Pretraining Principle 一章 https://www.cambridge.org/core/books/abs/multimedia-learning/pretraining-principle/01791D57F5D4164251269E6DF56A8BF1
- 做法：学习者先知道主要概念的名字和特征，再看讲解过程的材料，理解得更好。
- 采纳：学前地图本身就是「先认识名字和特征」这一步，所以每个专业词节点都配一句它是什么 / 干什么的解释；前置基础层最要紧。

### B-011 pytest · 临时目录自动保留最近几次

- 来源：https://docs.pytest.org/en/stable/how-to/tmp_path.html
- 做法：每次运行在 `tempfile.gettempdir()` 下自己专用的 `pytest-of-<用户>/` 里建目录；默认只留最近 3 次运行的目录，更早的自动删（可用 `tmp_path_retention_count`、`tmp_path_retention_policy` 调）。
- 采纳：放在系统临时目录下、本工具专用的子目录里；工具自己每次运行时顺手清旧的，不靠人记得。
- 不采纳：按「次数」保留。学习图一天可能画十几张，按次数会删掉当天还要看的图，改按天数。

### B-012 systemd tmpfiles.d · Age 字段

- 来源：https://man7.org/linux/man-pages/man5/tmpfiles.d.5.html
- 做法：给目录配一个 Age，周期清理时，比「当前时间减 Age」更旧的文件就删掉；看 mtime、atime、ctime，任何一个够新就不删。没写 Age 就不清理。
- 采纳：按年龄删，阈值写死在一处（`KEEP_DAYS = 7`）；几个时间取最新的那个：修改时间和创建时间（Windows）/ ctime（Linux、macOS）。复制会保留原文件的修改时间（Python `shutil.copy2` 文档："attempts to preserve file metadata"，https://docs.python.org/3/library/shutil.html#shutil.copy2），只看修改时间会把刚复制进来的旧图当场删掉；创建时间 / ctime 是复制那一刻。
- 不采纳：看 atime。Windows 可以关掉最后访问时间的更新（`fsutil behavior set disablelastaccess`，https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/fsutil-behavior），不能指望它。

### B-013 Windows 存储感知（Storage Sense）

- 来源：https://support.microsoft.com/en-us/windows/manage-drive-space-with-storage-sense-654f6ada-7bfc-45e5-966b-e24aded96ad5
- 做法：磁盘空间不够时自动清掉不需要的临时文件；「下载」文件夹默认不清，要用户自己选「多久没打开就删」。
- 采纳：用户自己放的东西（存档目录）默认不动，只清工具自己生成的临时文件。
- 不采纳：等磁盘快满才清。那时候已经堆了很多，这里每次渲染都清。

### B-014 npm link

- 来源：https://docs.npmjs.com/cli/v10/commands/npm-link
- 做法：在包目录里 `npm link`，会在全局目录建一个指向它的符号链接；用这个包的项目再链接过去。源码一改，用它的项目马上看到："any changes to … will be reflected in …"，不用反复重装。
- 采纳：各 AI 的入口是指向正本的链接，不是副本。改正本就等于所有 AI 一起更新。

### B-015 pip 可编辑安装（editable install）

- 来源：https://pip.pypa.io/en/stable/topics/local-project-installs/
- 做法：可编辑安装不复制文件，而是把开发目录加进 Python 的导入路径，改源码不用重装；只有改了项目元数据才要重装。
- 采纳：同上，「不复制、指回源头」。skill 没有元数据要注册，所以链接建好以后再也不用重装。

### B-016 GNU Stow

- 来源：https://manpages.debian.org/bookworm/stow/stow.8.en.html
- 做法：符号链接农场管理器（symlink farm manager），把一个目录里的东西用链接「装」到目标目录。目标位置已经有不归它管的文件时，默认报冲突、拒绝继续；`--adopt` 会把那个文件移进 stow 目录再继续。
- 采纳：用一张清单管所有入口；入口位置被副本占了，不直接删，先把副本移到备份目录（类似 `--adopt` 先收走），再建链接。
- 不采纳：`--adopt` 把旧文件并进源头，会覆盖正本里的内容。这里副本可能是旧版，只放备份，正本不动。

### B-018 git restore

- 来源：https://git-scm.com/docs/git-restore
- 做法：`--staged` 恢复暂存区、`--worktree` 恢复工作区，"Specifying both restores both."；`--source=HEAD` 从最新提交取内容；可以只给要恢复的路径。
- 采纳：只把被删的那些路径传给 `git restore --source=HEAD --staged --worktree`，暂存和没暂存的删除都能恢复，别的文件的改动不动。
- 不采纳：`git restore skill/` 整个目录恢复。会把正在改、还没提交的内容一起冲掉。

### B-019 git diff / git ls-files（判断是删空还是重构）

- 来源：https://git-scm.com/docs/git-diff 、https://git-scm.com/docs/git-ls-files
- 做法：`git diff <commit>` 看工作区相对某个提交的改动，`--diff-filter=D` 只列删除；`git ls-files --others --exclude-standard` 列出没跟踪的文件（"Show other (i.e. untracked) files"），并按 .gitignore 等排除。
- 采纳：删除用 `git diff --name-only --diff-filter=D HEAD` 数；`skill/` 里有没跟踪的新文件时，当作正在挪文件重构（普通移动时 git 只看到旧路径被删），只补回入口 `SKILL.md`。
- 不采纳：逐个比文件内容判断「是不是移动」。更准，但脚本要多读每个文件；「有没有新文件」已经能区分 10-19 那种全删和重构。

### B-020 Windows 任务计划程序 · 重复间隔

- 来源：https://learn.microsoft.com/en-us/windows/win32/taskschd/repetitionpattern-duration
- 做法：触发器可以设重复间隔；"If no value is specified for the duration, then the pattern is repeated indefinitely."
- 采纳：`-Schedule` 用一次性触发器加每小时重复、不设持续时间，就会一直每小时跑；再加一个登录时触发。不经过 AI，不花 token。
- 不采纳：更短的间隔（如每 5 分钟）。删空不常发生，一小时内恢复够用，跑太勤会更频繁地打扰正在做的重构。
